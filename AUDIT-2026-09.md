# Adversarial audit, September 2026

What was attacked, what was found, and what was left alone. Written so a reader can judge how
much the verdict on this repository is worth, rather than take an adjective for it.

Every finding is fixed and released. Reproduce any of it with `scripts/attack.py` and the
vectors in `testdata/vectors`.

## What was attacked

| Surface | Method | Result |
|---|---|---|
| Claim content&nbsp; | 30 mutations of payloads, timestamps, types | all caught |
| Chain structure | deleted, reordered, duplicated and renumbered claims, forged links, rewritten heads | all caught |
| Signature | truncated, byte-flipped, removed, foreign key, key_id disagreeing with key | all caught |
| Envelope | bundle_id, created_at, subject, unknown version, unknown chain profile | all caught, unknown declarations fail closed |
| Evidence | altered bytes, absent artifacts, locations escaping the directory | fixed, see finding 1 |
| JCS parser | duplicate object keys injected at top level and inside a payload | rejected outright |
| Signed surface | which members the producer signature covers | denylist, so unknown and future members are covered |
| Producer identity | a forged bundle carrying another product's name and id, signed by a fresh key | fixed, see finding 2 |
| Presentations | audience and nonce binding, replay of an unchallenged presentation | fixed, see finding 3 |
| Attestations | a counter-signature swapped for one from a key minted seconds earlier | fixed, see finding 5 |
| Merkle | domain separation, inclusion paths, consistency, sparse disclosure | sound, see below |
| Span | window coverage, recomputed counts, mid-adoption windows | discloses its own gaps |
| Anchors | corrupt tokens, backdated timestamps, proofs on unverified heads, unopenable proof types | sound, one note added |

## Findings

All five were the same defect: the verifier performed a real check and described it as a
stronger one. Not once did a check fail to catch what it claimed to catch.

**1. An altered artifact counted as missing.** `checkEvidence` did a content-addressed digest
lookup and ignored the `location` the bundle names, so an artifact absent from a disclosure and
an artifact sitting at its declared path with edited bytes landed in one counter. Neither
recorded a problem. An edited artifact printed VERIFIED and exited 0. Fixed in v1.2.0 with a
separate `ALTERED` line, a recorded problem, and `withinDir` rejecting locations that escape the
evidence directory, since `location` travels inside the bundle and is attacker-controlled.

**2. An unpinned run did not say the signer was unchecked.** Any key signs its own bundle. A
forged bundle carrying another producer's product name, bundle id and claim shapes, signed with
a key generated a minute earlier, reached the same verdict and exit code as the genuine one, and
nothing on the output said the identity had not been checked. Fixed in v1.3.0: a `pin NONE` line
and `producer_pinned` always emitted in JSON.

**3. A presentation's nonce was never printed.** Audience and nonce binding worked when demanded,
and the nonce, which is the entire replay defense, appeared nowhere. A presentation cut months
earlier for a different reviewer verified clean against anyone running the bare command. Fixed in
v1.4.0.

**4. A notice written for a passing state appeared beside a failing one.** The unpinned notice
printed above `ALTERED` and `NOT VERIFIED`, where "the bundle was signed" reads as partial
reassurance rather than as the open question it is. Fixed in v1.4.1 by gating both notices on the
whole verdict rather than on the local check that motivated them. Found by a peer's mutation test
on a different codebase, applied here.

**5. A counter-signature named a key and read as a party.** Attestations sit outside the producer
signature so a counterparty can vouch after the fact, which means any holder can attach one,
signed by any key, under any role. Swapping a genuine attestation for one from a fresh key under
the role `independent-auditor` verified clean and reported `vouched independent-auditor`. Of every
check here this is the one whose entire value is the identity behind it, and it was the only one
with no way to check that identity. Fixed in v1.5.0 with a repeatable `--attestor`, applied to
claim and head attestations alike.

## What held up

The cryptography and the structural verification did not yield under direct attack.

The JCS canonicalizer rejects duplicate object keys outright, at the top level and inside a claim
payload, which is a signature-bypass class a great deal of JSON tooling falls to. The producer
signature is denylist-based, so a member nobody has invented yet is covered rather than floating
unsigned. Merkle hashing carries RFC 6962 domain separation and is checked against a vector file
an independent implementation produced from the RFC alone, which is what separates being correct
from being self-consistent. Anchor proofs record a problem on bad base64, on a failed
verification, and on a timestamp preceding the entry it covers.

Merkle reporting was already doing what the rest of the verifier had to be taught: it names the
tree size against the number of leaves actually proved, and says outright that a bundle without a
consistency proof does not establish the log only ever appended.

## What was not attacked

The rfc3161 parsing internals were read, not fuzzed. Selective disclosure was read closely and
exercised through its vectors, not attacked with generated bundles. Neither is a claim of
correctness, and both are the obvious next targets.

**Update, 2026-09-20.** The rfc3161 gap is closed: the token parser is now fuzzed
(`rfc3161/fuzz_test.go`, seeded with the genuine token vector), alongside the bundle parser
and the canonicalizer, roughly fourteen million adversarial executions with no crash and no
fixed-point violation. The same pass added `internal/bundletest`, a builder that constructs
signed bundles through the real seal primitives, and `internal/cmd/integration_test.go`, an
end-to-end table through the actual CLI entry point asserting exit codes and rendered words
together, since every finding above lived between what was checked and what was said.
Selective disclosure remains vector-exercised rather than builder-attacked, and remains the
next target.

## The general lesson

A verifier that reports a discrepancy without letting it reach the verdict is worse than one that
does not check at all, because it manufactures confidence. One that stays silent about a check it
never performed is worse still. Any new check here should answer two questions in its own code
comment: does failing it change the verdict, and is skipping it visible. If either answer is no,
the reason belongs in writing.
